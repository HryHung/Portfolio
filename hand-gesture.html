09 / ENGINEERING CASE STUDY

Hand Gesture Unlock.

Real-Time Computer Vision Application

OVERVIEW

A webcam application that registers a static hand gesture and compares it with live input to change an on-screen lock state. Pretrained hand-landmark detection feeds geometric feature extraction and rule-based matching, with intermediate results visible in Streamlit.

DESIGN / BUILD / EVALUATE

Engineering Approach

The prototype explores a complete computer-vision workflow using an ordinary webcam. Its value is in connecting capture, geometric representation, reference registration, and visible feedback—not in establishing security-grade authentication.

01

Capturing and representing the hand

OpenCV captures webcam frames and converts them to RGB for MediaPipe Hands. The pretrained detector returns 21 landmarks per hand, providing a structured geometric representation for the application’s own analysis.

Instead of classifying the raw image directly, the application calculates finger configuration from those landmarks. The interface can display the camera feed and landmark overlay, making it possible to inspect the representation before interpreting a match result.

02

A ten-feature descriptor and a registered reference

The descriptor contains finger count, five individual finger angles, and four inter-finger angles. The geometric angles are computed from landmark vectors; together they represent the current static hand configuration.

Registration stores the reference feature vector in Streamlit session state. During comparison, finger count must match exactly, while the nine angular features must fall within a relative ±50% tolerance of the saved values. The result is rule-based matching of a reproduced gesture, not a learned identity model.

03

Interface feedback & evaluation conditions

Streamlit provides camera controls, reference registration, verification, and optional overlays. Saved, unlocked, and wrong-password states make the workflow visible. Showing intermediate features also helps explain a mismatch and supports debugging.

The report describes approximately 20–30 FPS, including a stated 30 FPS test at 720p. Finger-count accuracy is reported at approximately 98% under good lighting with a simple background. Gesture-match accuracy is reported at approximately 90–95%, depending on how consistently the gesture is reproduced. Low light, occlusion, and hand rotation can reduce stability.

No test-set size, participant count, or false-accept/false-reject evaluation is provided. The implemented workflow matches static gestures; dynamic sequences and stronger authentication remain future work.

EVIDENCE & OUTCOMES

Results & Achievements

  • Working webcam-based gesture registration and static matching.
  • Reported 20–30 FPS, including a stated 30 FPS at 720p test.
  • Reported approximately 98% finger-count accuracy under good lighting and a simple background.
  • Reported approximately 90–95% gesture-match accuracy, dependent on reproduction consistency.
  • Intermediate features and matching states visible for explanation and debugging.

Evidence limits

Test-set size, participant count, and false-accept/false-reject rates are unspecified. These reported demonstrations are not a validated security benchmark.
